This example shows a common pattern, where an organization creates a "suite" of modules that build on top of common resource primitives in an opinionated way. These allow organizations to have common concepts and code between teams that all follow the organization's best practices.

As with the previous example, we see the org transition from [./modules](./modules) to modules enhanced with [./symbols](./symbols).

This example is a bit over-simplified, but has enough wiring to get the point across. Even in these local scenarios, it is clear to see how sharing symbols would make extending and refactoring this organization's codebase easier.
